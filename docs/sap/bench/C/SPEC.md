# Shifting a formula to another cell gives wrong results for some formulas

- KNOWN: The file is src/zcl_excel_common.clas.abap (abap2xlsx, class ZCL_EXCEL_COMMON). It has a static routine that takes a formula as text and the number of columns and rows to move it by. It returns the formula as Excel would write it after the formula is copied that far: relative cell references move, `$` absolute parts stay, everything else stays as written.
- KNOWN: Symptom 1, spaces. A formula that contains spaces does not always come back with its spaces. Spaces inside a table reference (for example `SUM(Sales[Q1 total])`) and spaces around an operator (for example `D7 & E7` moved down one row) should stay exactly as they were written, with only the cell references moved (`D8 & E8`). The same holds for spaces and trailing spaces around function arguments.
- KNOWN: Symptom 2, things that look like cell references but are not. The text before the `!` of a sheet name is not a cell reference. A sheet name that ends in digits (`Data2!C3`) or a quoted sheet name with a space (`'My sheet'!C3`) is wrongly treated as if it were a cell address; only the address after the `!` should move (by 1 column and 1 row: `Data2!D4` and `'My sheet'!D4`). A quoted sheet name that happens to look like a cell address (`'B2'!$C$3`) must be left alone. A defined name that has letters, an underscore and a digit (for example `G_2`) is not a cell address and must be left alone. Text inside double quotes is not a formula part and must be left alone, even if it contains something that looks like a reference.
- KNOWN: Everything that works today must keep working: relative and absolute references, ranges, names, string literals, external workbook references, references that move off the sheet (`#REF!`), the empty formula, rows that move up or down by any amount, and a shift of 0 columns and 0 rows.
- KNOWN: Change only what is needed in that file. Keep every other line exactly as it is: no new methods, no changes outside that routine, no reformatting.
